# Describe design considerations for applications that use foundation models (FMs)

This task covers the choices you make when building an application on a foundation model: which model to use, how to tune its output, how to give it your own data, how to store that data, how much each customization approach costs, and when to add an agent. Expect scenario questions that ask you to pick the simplest, cheapest option that meets a stated need.

## Key concepts

### Selecting a foundation model

No single model fits every job. Compare candidates on:

- **Modality**: the inputs and outputs supported, such as text, images, or embeddings.
- **Cost and latency**: smaller, simpler models are generally cheaper and faster per request. Features such as prompt caching (reusing a repeated prompt prefix) and distillation can lower cost further.
- **Languages**: support and quality for each language you need.
- **Model size and complexity**: larger models usually reason better but cost more and respond more slowly.
- **Customization**: whether the model can be fine-tuned or distilled.
- **Input and output length**: the context window must fit your prompt plus retrieved context, and the output limit must fit the answer.

Amazon Bedrock gives access to many models through one service, so you can test several against your own prompts.

### Inference parameters

Inference parameters change how a model produces a response without changing the model.

- **Temperature**: low values favor high-probability tokens and give consistent output. High values flatten the distribution and give more varied, creative output.
- **Top K and Top P**: limit the pool of candidate next tokens. Lower values narrow the pool.
- **Length**: maximum response length caps output tokens. A limit that is too low truncates answers, and longer outputs cost more. Stop sequences end generation at a chosen string.

### RAG and Amazon Bedrock Knowledge Bases

Retrieval Augmented Generation (RAG) retrieves relevant content from a data source and adds it to the prompt so the model answers from current, private information. No retraining is needed, and you refresh knowledge by updating the data source. Typical uses are support chatbots, internal search, and policy assistants.

Amazon Bedrock Knowledge Bases manages the pipeline: ingest documents, split them into chunks, create embeddings, store them in a vector index, retrieve at runtime, and augment the prompt.

### Vector databases for embeddings

An embedding is a numeric vector that represents meaning. Vector stores support similarity search over embeddings. AWS options include:

- Amazon OpenSearch Service, recommended by AWS for use with Amazon Bedrock.
- Amazon Aurora PostgreSQL-Compatible Edition and Amazon RDS for PostgreSQL, using the pgvector extension.
- Other databases, such as Amazon Neptune, Amazon DocumentDB, and Amazon MemoryDB, also appear in AWS vector database guidance.

### Customization cost tradeoffs

| Approach            | What it does                                  | Relative upfront cost                 |
| ------------------- | --------------------------------------------- | ------------------------------------- |
| In-context learning | Adds instructions or examples to the prompt   | Lowest                                |
| RAG                 | Retrieves your data at request time           | Low to moderate                       |
| Fine-tuning         | Trains the model on labeled data              | Higher                                |
| Model distillation  | Trains a smaller student from a teacher model | Higher up front, lower inference cost |
| Pre-training        | Builds a model from large datasets            | Highest                               |

### AI agents

An agent uses a foundation model to plan steps, call tools and APIs, query knowledge bases, and work toward a goal. Business uses include customer service, claims processing, travel booking, and IT workflow automation.

## Key terms

| Term            | Meaning                                                  |
| --------------- | -------------------------------------------------------- |
| Embedding       | Numeric vector that represents the meaning of data       |
| Vector database | Store that indexes embeddings for similarity search      |
| Chunking        | Splitting documents into smaller pieces before embedding |
| Temperature     | Parameter controlling randomness of token selection      |
| Context window  | Maximum amount of input a model can process              |
| Action group    | Set of API actions an agent can perform                  |

## Comparisons

- **RAG vs fine-tuning**: RAG supplies fresh facts at request time. Fine-tuning changes model behavior or style and needs training.
- **Fine-tuning vs distillation**: fine-tuning adapts one model. Distillation transfers a larger model's behavior to a smaller, cheaper one.
- **Model vs agent**: a model returns generated content. An agent plans and takes actions.

## Exam tips

- Frequently changing data points to RAG, not repeated training.
- Cheapest first: prompt changes, then RAG, then fine-tuning, with pre-training last.
- Low temperature means consistent. High temperature means creative.
- Truncated output points to the maximum output length.
- "Already uses PostgreSQL" points to pgvector on Aurora or RDS.
