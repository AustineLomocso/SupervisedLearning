# Describe the training and fine-tuning process for FMs

This task covers how a foundation model (FM) is built and then adapted: the stages of training, the methods used to fine-tune, and how to prepare the data. Exam questions usually describe a goal and the available data, then ask which technique or data practice fits.

## Key concepts

### Stages of training an FM

- **Pre-training** trains a model from scratch on very large, diverse datasets, usually with self-supervised objectives. It is by far the most expensive stage and produces the base model with broad abilities.
- **Fine-tuning** continues training a pre-trained model on a smaller, task-specific dataset. The model weights change. In Amazon Bedrock, supported models are fine-tuned with labeled data supplied in JSONL files.
- **Continued pre-training** keeps training on additional unlabeled data from a domain (for example law or medicine) so the model absorbs new vocabulary and knowledge.
- **Distillation** transfers knowledge from a larger teacher model to a smaller student model. In Amazon Bedrock Model Distillation, the teacher generates responses to your prompts, sometimes with synthetic data, and the student is fine-tuned on them. You can also reuse prompts or prompt-response pairs from invocation logs. The result is a faster, cheaper model for a specific use case.

### Methods for fine-tuning

- **Instruction tuning** trains on prompt-response pairs so the model learns to follow instructions and respond in a desired style or format.
- **Domain adaptation** adapts a model to a specific field. Use continued pre-training when you have unlabeled domain text, and fine-tuning when you have labeled examples.
- **Transfer learning** reuses what a model learned on one task as the starting point for another, which cuts data and compute needs. Fine-tuning an FM is transfer learning.
- **RLHF** aligns outputs with human preferences. Humans write or rank responses, a reward model learns those preferences, and the language model is optimized against the reward model.

### Preparing data for fine-tuning

- **Curation:** remove duplicates, errors and contradictions. Quality beats volume.
- **Labeling:** supervised fine-tuning needs desired outputs. Human annotators or reviewers create or check prompt-response pairs, following clear guidelines so labels are consistent.
- **Representativeness:** data should cover the real inputs, user groups and edge cases. Missing groups lead to weak performance on them.
- **Size:** more data helps only when it is good. Each model has minimum and maximum record counts, and a validation dataset helps detect overfitting.
- **Governance:** know the data's source and permissions, control access, and remove or anonymize personal and confidential data, because models can memorize training content.
- **RLHF data:** needs human-written demonstrations and human rankings of multiple responses to the same prompt.

## Key terms

| Term              | Meaning                                                                                   |
| ----------------- | ----------------------------------------------------------------------------------------- |
| Base model        | The pre-trained FM that later stages adapt                                                |
| Teacher / student | The larger source model and the smaller model trained from its outputs in distillation    |
| Reward model      | A model trained on human rankings to score how much people would prefer a response        |
| Overfitting       | The model memorizes training data and generalizes poorly, shown by rising validation loss |
| Synthetic data    | Training examples generated by a model rather than collected from people                  |

## Comparisons

| Technique                        | Data needed                                | Typical goal                        |
| -------------------------------- | ------------------------------------------ | ----------------------------------- |
| Pre-training                     | Huge, diverse, mostly unlabeled            | Build broad general ability         |
| Continued pre-training           | Unlabeled domain text                      | Add domain knowledge and vocabulary |
| Fine-tuning / instruction tuning | Labeled prompt-response pairs              | Improve a task, style or format     |
| Distillation                     | Prompts (optionally labeled pairs or logs) | Smaller, cheaper, faster model      |
| RLHF                             | Human demonstrations and rankings          | Align with human preferences        |

## Exam tips

- Unlabeled domain text points to continued pre-training; labeled prompt-response pairs point to fine-tuning or instruction tuning.
- "Smaller, cheaper, lower latency" with a larger model already in use points to distillation.
- Human rankings and a reward model always point to RLHF.
- Poor results on one customer group is a representativeness problem; fix the data, not the model size.
- Contradictory or noisy labels cause inconsistent outputs; curate before adding more data.
- Fine-tuning changes model weights. Prompt engineering and retrieval augmented generation do not.
